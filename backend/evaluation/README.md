# AI evaluation

The committed `results/baseline.json` was generated by the actual offline keyword runner. It is **not an LLM result**. It scores 44% label accuracy over 25 requirements in 12 synthetic cases. Its requirement precision/recall are 100% only because it receives the expected requirements directly (oracle extraction).

## Reproduce

From `backend`, with the Python environment installed:

```bash
python -m evaluation.run --mode baseline --output evaluation/results/baseline.json
python -m evaluation.run --mode replay --predictions evaluation/results/baseline.json --output evaluation/results/replay.json
```

Live Groq evaluation is explicit, opt-in, and uses only the fictional data in `dataset.py`:

```bash
python -m evaluation.run --mode live --confirm-free-plan --max-cases 2 --output evaluation/results/live-small.json
```

First verify that the configured Groq account uses its Free plan. A key must be set in `backend/.env` or the environment. Start with two cases, inspect the output, then run the full set. Calls are spaced 15 seconds apart with no automatic retries. Rate-limit or configuration errors stop further requests. Missing/unrun cases count against valid-response rate and recall; do not present a partial run as a successful full benchmark.

## Metrics

- **Valid response rate:** fraction of cases producing a usable response after schema and evidence checks. This is not factual accuracy.
- **Requirement precision/recall:** extraction coverage aligned by canonical job quotation. Longer quotations can match a full canonical passage; short fragments do not get credit. Review unmatched extractions before concluding they are false positives.
- **Label accuracy:** correct strong/partial/missing assessments over all expected requirements, including unextracted requirements as errors.
- **Macro F1:** equally weights the three assessment labels. Unmatched expected requirements count as false negatives. Extra extracted requirements are penalized separately by precision, not assigned a synthetic class.
- **Priority accuracy:** required/preferred classification on aligned requirements.
- **Score MAE:** absolute difference from the manually labelled weighted score on valid cases only. Read alongside valid-response rate.

Live outputs also record the model, prompt version/hash, token usage, and response duration. Prompt changes must get a new version and a fresh comparison report; do not overwrite reports from a previous experiment if you need historical comparison.

## Dataset and interpretation

Cases cover direct evidence, semantic paraphrases, partial experience, absent skills, negation, preferred qualifications, transferable skills, and a resume injection attempt. Labels were written during development and need independent review; a legitimate disagreement is possible, especially on partial matches.

This is a small development challenge set, not a representative hiring benchmark. There is no held-out independent test set yet. Do not claim that CareerLens improves shortlisting, predicts hiring, or achieves a general accuracy percentage based on these cases. The baseline's weaknesses motivate the experiment; an LLM improvement has to be measured rather than assumed.

A real Qwen 3.8 27B run is saved in `results/live-qwen-full.json`: 12/12 valid responses, 84% label accuracy, macro F1 0.7202, score MAE 8 points. Three of four partial matches were classified as missing; nine of ten strong matches were strong, one partial. This remains a development-set measurement, not independent validation. Failed initial model/configuration probes are retained as separate files.

The verified output budget is 2,200 tokens. Large resumes or many requirements can still exhaust free-tier quotas or truncate responses; failures are surfaced rather than silently presented as complete results. No live-model evaluation was performed without a configured key. Never label baseline or fixture outputs as Groq results.
